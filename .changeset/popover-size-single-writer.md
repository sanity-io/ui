`Popover` no longer mirrors its width into refs and state behind Floating UI's back. The `width` property's resolved width and the max width from it and the boundary are rendered on the card, except where the `size` middleware writes them to the element itself during the positioning pass: the width when it matches the reference element's (`matchReferenceWidth`), and the max width when `constrainSize` caps it to the available room as well. Every size style has one writer now — React never touches a style it did not render — so the passive effect that re-applied `width` and `maxWidth` after every render, the refs that fed the middleware and the `referenceWidth` state the middleware set from inside the pass are gone. That state cost one commit per open and per reference resize of a `matchReferenceWidth` or `constrainSize` popover. The middleware exposes its inputs as `options` the way Floating UI's own middleware do, so changing `constrainSize`, `matchReferenceWidth` or the margins of an open popover now reaches the next positioning pass (it used to keep the first values), and turning either flag off clears the size styles the middleware had written (the max height used to stick). A `constrainSize` popover whose boundary resizes while it is open repositions once for the new cap, which also re-reads the room within the boundary instead of writing the unclamped cap.
