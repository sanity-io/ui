`Tooltip` and `Popover` no longer schedule a state update when the element they are attached to mounts, unmounts, or is hidden and shown again by an `<Activity>`, so revealing them inside a React 19.3 `<ViewTransition>` starts the animation without a re-render in the way, and a sync flush while the browser prepares that transition no longer cancels it. The child's own `ref` holds the element from the commit that mounts it on (it was set one render later before), follows a replaced element, and a `ref` whose identity changes every render — an inline `ref={(el) => …}` — is swapped the way React swaps a `ref` prop, without Floating UI or the popover's intent listeners noticing. `Layer` attaches a forwarded `ref` once, rather than again on every render, which for a shown tooltip was a nested re-render per render of its parent. (`MenuButton`'s equivalent is in #3144.)

The ref callback the cloned child receives used to set the element into state (the tooltip's own, and Floating UI's through its `refs.setReference`), which React schedules at Immediate priority as it runs in the commit phase. Inside a `<ViewTransition>` such an update is committed as soon as the transition that reveals (or hides) the element is ready to animate, right before its first frame, which held the animation up by the re-render of every tooltip and popover in the revealed tree, and left a pending sync update that made React skip the transition should anything flush sync work while the browser was still preparing it (a `flushSync`, or React restoring the value of a controlled input). The element now lives in a ref. Floating UI is handed it when the card it positions mounts, which is when the tooltip is shown or the popover opens, so the update it schedules for the element rides along with the one for the card; a popover's intent listeners (which pre-render it when the pointer enters, presses or focus lands on its reference) are attached from the same ref callback. Mounting a closed tooltip or popover no longer re-renders it in a nested, Immediate-priority commit right after the one that mounts it; the deferred commit in which React pre-renders the content of its hidden `<Activity>` stays, as for any hidden `<Activity>`.
