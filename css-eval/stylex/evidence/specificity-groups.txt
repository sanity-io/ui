=== separately compiled sheets (precompiled library + consumer app) ===
library  padding      → .x7w9gsk:not(#\#)  (1 bump(s): level 1 is group #1 of the library sheet)
app      padding-top  → .xexx8yu  (0 bump(s): level 4 is the ONLY group of the app sheet)
→ On an element combining both (stylex.props(lib.root, app.flush)), the longhand `padding-top: 0` does NOT reliably beat the shorthand `padding: 12px`: equal or lower specificity, so stylesheet order decides. StyleX semantics require the longhand to win.

=== one compile over both modules (the model StyleX is designed for) ===
padding      → .x7w9gsk:not(#\#)  (1 bumps)
padding-top  → .xexx8yu:not(#\#):not(#\#):not(#\#):not(#\#)  (4 bumps)
→ longhand wins regardless of order.

=== with useLayers: true (layer names are also index-based) ===
@layer priority1;
@layer priority1, priority2, priority3, priority4, priority5;
→ `priority1` means level 4 in the app sheet but level 0 in the library sheet; the first `@layer` statement on the page fixes the layer order for all sheets.

Scope: this only matters when ONE element merges styles from two precompiled sheets (a library style prop + app override), or shorthand/longhand pairs straddle sheets. Two versions of a library never share an element. Mitigations: (a) compile library source in the consumer (StyleX default model, `externalPackages`), (b) make bumps absolute (`Math.floor(priority / 1000)` instead of the group index — a one-line upstream change), (c) libraries avoid shorthands in styles consumers may override.
